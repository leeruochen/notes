## Goal
Read mailboxes with found creds. Emails hold passwords, keys, and hints. POP3(110)/IMAP(143) is a loot service used after you find creds.

**Checklist**
- [ ] banner / software?
- [ ] have creds to log in?
- [ ] plaintext, STARTTLS, or implicit TLS?
- [ ] mail with passwords / attachments / internal hosts?

# Commands

### Step 1: Banner
```bash
nmap -p110,143,993,995 -sC -sV $IP
```

### Step 2: Plaintext, STARTTLS, or implicit TLS

```text
143 IMAP   -> plaintext or STARTTLS
993 IMAPS  -> implicit TLS

110 POP3   -> plaintext or STARTTLS
995 POP3S  -> implicit TLS
```

Search aliases: STARTTLS IMAP, STARTTLS POP3, `openssl -starttls imap`, `openssl -starttls pop3`.

```bash
openssl s_client -connect <host>:143 -starttls imap -crlf
openssl s_client -connect <host>:110 -starttls pop3 -crlf
```

Add `-servername <hostname>` only when a discovered hostname and SNI are relevant. After TLS succeeds, enter the existing IMAP or POP3 commands below in the same session.

**Verify:** TLS negotiation completes and the server returns the expected IMAP or POP3 greeting/capability response.

**Fail:** Certificate-name warnings may require the discovered hostname and `-servername`. Handshake or protocol errors mean re-check the port, fingerprint, and whether the service expects plaintext, STARTTLS, or implicit TLS.

### Step 3: Guarded mailbox authentication

Search aliases: IMAP default credentials, POP3 default credentials, mailbox identity, username as password.

**Evidence-backed hypothesis testing != password spraying/brute force**

Require one strongly supported mailbox identity from WHOIS/contact data, another message, application configuration, account enumeration, or an identity already established elsewhere.

1. Exact password already recovered for this identity? Test that pair once.
2. Product or environment default supported by evidence? Test only that exact default.
3. Username as password is a justified hypothesis? Make one deliberate test.
4. Tiny evidence-backed candidate set? Check lockout risk, then test only those candidates.
5. None of the above, or lockout risk is unknown/unacceptable? Stop and find better evidence.

Stop immediately on lockout evidence, throttling, or repeated failures. Do not turn the branch into a Hydra list or broad guessing.

**Verify:** IMAP `LOGIN` or POP3 `PASS` succeeds for the exact username/password pair. Preserve that pair together.

**Next:** Validate reuse narrowly through [[01_credentials_and_spraying]], then enumerate the mailbox with the protocol commands below.

### Step 4: POP3 login + read
```bash
nc -nv $IP 110
# or TLS:  openssl s_client -connect $IP:995
USER <user>
PASS <pass>
LIST                    # list messages
RETR 1                  # read message 1
DELE 1                  # delete (if needed)
QUIT
```

### Step 5: IMAP login + read
```bash
nc -nv $IP 143
# or TLS:  openssl s_client -connect $IP:993
a LOGIN <user> <pass>
a LIST "" *
a SELECT INBOX
a FETCH 1 BODY[]
a LOGOUT
```

### Step 6: Attachments
```bash
# multipart/mixed = attachment. base64 block -> decode:
echo "BASE64_DATA" | base64 -d > attachment.pdf
# many messages? point Thunderbird / Evolution at IMAP $IP with the creds
```

### Helpline
```bash
# READING BANNERS: "+OK POP3 ready" / "* OK IMAP4 ready" = login with FOUND creds (you can't easily brute these).
#   Dovecot = standard Linux mail. Exchange/Microsoft = AD environment (note it).
# WHAT TO LOOK FOR IN MAIL:
#   LIST shows messages -> RETR every one. a password in an email -> try it on ssh/rdp/web/smb NOW
#     (credential reuse is the most common OSCP pattern).
#   email mentions a file path -> use LFI/traversal to read that file.
#   base64 attachment -> decode; a .pfx -> extract cert/key -> WinRM cert auth (HTB Timelapse pattern).
# HOW YOU GOT HERE: usually SMTP phishing or a James pw-reset gave the creds (HTB SneakyMailer: IMAP -> FTP creds).
# Exchange/Outlook detected -> check ProxyLogon/ProxyShell / NTLM-leak CVEs (HTB Mailing).
# no exact cred -> use the guarded mailbox decision once; otherwise stop and find better evidence.
```
